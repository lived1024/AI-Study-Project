## Waterfall vs Agile
![Waterfall vs Agile](Waterfall%20vs%20Agile.png)
### Waterfall
- **순차적 개발 방법론**: 요구사항 분석 → 설계 → 개발 → 테스트 → 배포 → 유지보수 순서로 진행
- **특징**:
  - 각 단계가 완료되어야 다음 단계로 진행
  - 초기에 모든 요구사항을 명확히 정의
  - 변경사항 대응이 어려움
  - 문서화가 체계적
- **장점**: 예측 가능성, 명확한 계획
- **단점**: 유연성 부족, 고객 피드백 반영 어려움

### Agile
- **반복적 개발 방법론**: 짧은 주기(스프린트)로 반복하여 점진적으로 개발
- **특징**:
  - 2-4주 단위의 스프린트로 개발
  - 지속적인 고객 피드백 수집
  - 변경사항에 유연하게 대응
  - 개발팀과 고객 간의 협업 중시
- **장점**: 빠른 피드백, 유연한 대응, 고객 만족도 향상
- **단점**: 예측성 부족, 문서화 상대적으로 부족



## DevOps vs MLOps
![DevOps vs MLOps](DevOps%20vs%20MLOps.png)
### DevOps
- **개념** : 소프트웨어 개발 과 IT 운영의 통합
- **목적** : 소프트웨어 개발과 배포를 자동화하고 효율적으로 관리
- **주요 요소** : 자동화, 지속적 통합(CI), 지속적 배포(CD), 모니터링, 인프라 관리, 개발과 운영의 협업
- **역사**
  1. **2000년대 초반** : 애자일 방법론이 널리 채택되며 개발과 운영 간의 협력이 필요해짐
  2. **2008년** : DevOps 용어 등장
  3. **2009년** : 벨기에에서 첫 DevOpsDays 행사 개최
  4. **도구와 프레임워크의 발전**
     - Jenkins (CI/CD 도구)
     - Docker (컨테이너화)
     - Kubernetes (컨테이너 오케스트레이션)
     - 지속적 통합(CI)와 지속적 배포(CD) 파이프라인이 널리 채택
     - 자동화된 빌드, 테스트, 배포 파이프라인을 구축하여 개발 주기를 단축하고 안정성 향상
  5. **클라우드 컴퓨팅의 부상** : AWS, Azure, GCP 등의 클라우드 서비스가 인프라 확장성과 유연성을 제공하여 DevOps 도입 가속화
  6. **마이크로서비스 아키텍처(MSA) 도입**
      - 애플리케이션을 작은 서비스 단위로 분할하여 개발 및 배포 속도를 높이고 유연성을 확보
      - 구글에서 직함으로 만들기 시작

### MLOps
- **개념** : 머신 러닝(ML) 모델 개발과 운영(배포, 유지보수)의 통합
- **목적** : ML 모델의 개발, 자동화, 배포, 모니터링, 관리 자동화
- **주요 요소** : 데이터 관리, 데이터 엔지니어링, 모델 훈련 및 배포, 지속적 학습, 모니터링

#### MLOps vs LLMOps
- MLOps  : 머신러닝 운영 전반
- LLMOps : 그중에서도 LLM이라는 까다롭고 복잡한 모델을 성공적으로 운영하기 위한 특화되고 전문화된 분야
